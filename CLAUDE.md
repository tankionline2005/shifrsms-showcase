# Shifr SMS — памятка для Claude

Telegram-бот (aiogram 3) перепродаёт одноразовые SMS-активации площадок Grizzly, SMSPool, 5SIM, Onlinesim.
Всё управляется из веб-панели `/admin` (FastAPI + Jinja2). PostgreSQL в Docker на сервере, SQLite локально.
Пользователь общается по-русски; бот и панель — только на русском.

## Главное в коде
- `app/catalog.py` — прайсы площадок в памяти, уровни цены страны (`Quote.levels`), ценовые категории режима
  «Авто» по всем странам (`auto_levels`, замена — `auto_level_at`), карантин «фантомов», популярность.
  Пользователю (бот, сайт, API) — `auto_choices`: без самой дешёвой категории (самая ненадёжная, остаётся ориентиром).
- `app/orders.py` — покупка (до 5 поставщиков уровня, самые надёжные первыми; `country_id=None` — «Авто»),
  отмена и замена без вопроса о причине, фоновая отмена ненужных номеров (`DiscardedOrder`, итог `lost`).
- `app/quality.py` — надёжность только по НАШЕЙ статистике (данным площадок не доверяем), по ступеням
  сервис → страна → поставщик в стране, каждая сглажена к ступени выше.
- `app/bot/channels.py` — каналы и группы бота (`BotChat`, связка канал ↔ группа обсуждения) и рекламный
  комментарий под каждым новым постом канала (раздел панели «Каналы»); текст кнопки в бота — свой у каждого
  сообщения (`ChannelMessage.button_text`, пусто — «🤖 Открыть бота»); ссылка кнопки — своя (`button_url`, например
  с UTM-меткой) только у канала не реферала, у канала реферала — всегда его реферальная ссылка.
  «Шаблон сообщения» (`ChannelMessage.chat_id == channels.TEMPLATE` = 0, только в админке) копируется первым
  сообщением в каждый новый канал (`channels._save` → `apply_template`). Основной роутер `handlers.py` —
  только для личных чатов.
- `app/utm.py` — UTM-метки: ссылка `t.me/<бот>?start=utm_<метка>` (латиница, цифры, _ и -, до 60 символов,
  части через дефис: источник-кампания-объявление). Новый пользователь закрепляется за первой меткой (`User.utm`),
  каждый такой /start — `UtmStart`. Панель «UTM-метки» (`/utm`): конструктор ссылки и статистика по меткам/источникам;
  в «Пользователях» поиск `utm:<метка>`.
- `app/bot/support.py` — поддержка: «Информация» → «💬 Поддержка» (только кнопкой) — обращение = тема в группе
  поддержки (настройка `support_chat`, группа с темами, бот — админ с «Управление темами»). Сообщения пользователя
  бот копирует в тему, ответы из темы шлёт пользователю от себя («💬 Поддержка» + «✍️ Ответить»); `//` — заметка
  для своих. Закрывают только владельцы: кнопка на карточке, /close или закрыть тему. `SupportTicket`.
  Карточка пользователя в теме — «🔄 Обновить» и сама раз в минуту, пока обращение открыто (`refresh_cards`,
  правится только при изменениях); при закрытии — последний раз и без кнопок.
- Руководство и база знаний для сотрудников поддержки — `app/web/guide/support-guide.md`, публично на
  `/support-guide` (`app/web/support_guide.py` собирает страницу из md, оформление — `app/web/guide/page.html`).
  Меняется бот — проверить, не устарело ли руководство.
- `app/tgcheck.py` — проверка номеров Telegram перед выдачей (`orders._buy`): аккаунты владельцев (`TgChecker`,
  Telethon, сессии зашифрованы ключом из SESSION_SECRET; TG_API_ID/TG_API_HASH в .env) по очереди делают
  contacts.resolvePhone; найден аккаунт (в т. ч. удалённый) — номер не выдаём, `discard` → отмена в фоне, берём
  другой (до 3 у поставщика). Проверить некем — выдаём без проверки + уведомление. Панель «Проверка Telegram»
  (`/tgcheck`, только владельцы): вход номер → код → облачный пароль; лимит в сутки и пауза — в «Настройках».
- Главная `/` — один экран: что за сервис, две одинаковые кнопки «Открыть Telegram-бота» / «Продолжить в браузере»,
  партнёрка — ссылкой в подвале рядом с документами (`app/web/landing/home.html`, в том же
  стиле; шрифты, иконка и фон — общие с лендингом партнёрки, ссылки на документы — из настроек terms_url/privacy_url).
- Лендинг партнёрской программы — `/partnership` (старый `/become-partner` перенаправляется; `app/web/landing.py`, страница `app/web/landing/partnership.html`,
  статичный HTML от владельца — шрифты в `landing/fonts/`, превью ссылки `landing/og.jpg`, иконка вкладки `landing/icon.png`, ссылки «Подключить канал» в личку менеджеру прямо в файле; сервер только
  подставляет `{{CTA_URL}}`/`{{PAGE_URL}}`, если они есть).
- `app/user_refs.py` — приглашения обычных пользователей: «👥 Пригласить друга» в «👤 Профиль» и на сайте, ссылка на САЙТ
  `<сайт>/r/<код>` (`user_refs.link`) — после первого подтверждённого пополнения, Telegram не нужен. `/r/` запоминает код в
  cookie `invite` на 90 дней (первый переход, чужие не перезаписывают) и ведёт в каталог; засчитывают регистрация на сайте,
  вход через Telegram нового для бота человека (`TgAuth.invite` → `/start web_`) и кнопка бота на главной (`?start=u_<код>`).
  Старые `?start=u_<код>` работают. Кодов у человека несколько (`RefCode`; `User.ref_code` — основной, показывается).
  Новый пользователь закрепляется (`User.inviter_id`, навсегда; либо канал-партнёр, либо пользователь). Склейка
  аккаунтов: пригласившие обоих — пригласившие общего (даже давнего), разные — оба (`referral2_id`/`inviter2_id`, до двух
  всего, `referrals.attributions`), каждому половина своей доли; коды обоих продолжают работать. Пригласившему — на БАЛАНС БОТА (₽) та же доля, что
  каналам (`user_ref_revenue_percent` % цены, но ≤ `user_ref_profit_percent` % прибыли), один раз на заказ (`UserRefReward`),
  `Transaction.kind="referral"`, уведомление «🎉 +N ₽: ваш друг получил SMS». Вызывается из `owners.on_sms` — прибыль
  владельцев меньше на эту сумму. Меняется `MAIN_KB` — увеличить `ui.MENU_VERSION`: старым пользователям бот
  пришлёт новое меню один раз. `ensure_user` стоит и у `support.private`, и у основного роутера — «новый пользователь»
  определяется по обновлению, при котором его создали (иначе второй проход затирал флаг).
- Сайт `/shop` (`app/web/shop/`: `views.py` — страницы, `api.py` — API, `i18n.py` — RU/EN, `core.py` — вход, CSRF,
  шаблоны в `templates/`) — то же, что бот, в браузере, через те же `orders.*`, баланс один. Иконки сервисов — `logos.py`:
  векторные для самых популярных, остальные — `icons/*.webp` + `icons/map.json` (id сервиса → картинка; собраны из списка
  сервисов Grizzly и Simple Icons; `x-*.webp` — присланные владельцем), без иконки — только название. Каталог — по 150 («Ещё сервисы»), флаги — flagcdn.com.
  Аккаунты — `app/shop_accounts.py`: логин+пароль (`User.login/password_hash`), пользователь только сайта — id от
  `WEB_ID_BASE` (9e15; `is_tg()` — есть ли Telegram: бот ему не пишет, рассылки и уведомления его пропускают). Вход,
  привязка Telegram и сброс пароля — через бота: `/start web_<token>` → «✅ Да» (`TgAuth`, 5 мин, результат — только
  тому браузеру). Привязка = склейка (`merge`): всё сайтовое переезжает к пользователю бота, балансы складываются,
  отвязать нельзя; ключ API был у обоих — остаётся ключ сайта; заблокирован один — заблокирован общий; открытые обращения
  у обоих — остаётся из бота, с сайта закрывается со ссылками (`support.join_merged`). Поддержка с сайта —
  `support.web_send` в ту же тему; переписка сохраняется в `SupportMessage` (с 20.10.2026, раньше — не хранилась).
  Регистрация — с капчей `app/captcha.py` (3D-буквы в цветах сайта, три источника света, numpy; ответ только на сервере,
  одноразовый, 10 мин). В заказах на сайте не показываются отменённые, истёкшие и заменённые, в пополнениях — отменённые и истёкшие.
  API (ключ в профиле после первого пополнения, `User.api_key_hash`): REST `/api/v1/…` и совместимый с SMS-Activate
  `/stubs/handler_api.php` (коды сервисов и стран — Grizzly/SMS-Activate, иначе `s<id>`/`c<id>`). Главная — выбор
  «бот» / «в браузере».
- `app/partner_signup.py` — канал подключается к партнёрке сам: окно на лендинге (кнопки «Подключить»): ссылка на
  ПУБЛИЧНЫЙ канал (бот видит его описание, обсуждение и число подписчиков, не состоя в нём) → код `SHIFR-XXXXXX`
  создаётся только на шаге 2, привязан к каналу и браузеру, живёт 15 мин → код в описании канала → `referrals.create`,
  сразу вход в кабинет, уведомление владельцам. Условия (обсуждение не обязательно): подписчиков ≥ `partner_min_subscribers` (500),
  не партнёр, не в `PartnerBan` (туда попадает канал, у которого МЫ удалили реферала; «Сделать рефералом» снимает запрет).
- `app/referrals.py` — рефералы (друзья со своими каналами): кнопка под их постами ведёт на `?start=ref_<code>`,
  новые пользователи закрепляются навсегда, рефералу с каждой активации, где пришла SMS (`orders.apply_status` →
  `referrals.accrue`): `revenue_percent` % ЦЕНЫ (15%), но не больше `percent` % НАШЕЙ ПРИБЫЛИ (50%) — `referrals.share`,
  в $ по курсу ЦБ. Оба процента — у каждого реферала в «Каналах»; в кабинете реферал видит только «N% от стоимости».
- Веб: админка по секретному адресу `ADMIN_PATH` из `.env` (в шаблонах префикс `{{ A }}`), кабинет партнёра (реферала) —
  `/partner-dashboard` (`app/web/referral.py`, старый `/referral…` перенаправляется); страницы каналов общие (`app/web/channel_pages.py`, `scope` — какие каналы видны); у партнёра вкладка
  «Ваш канал» — свой вид (`_partner_channel.html`: цифры, шаги настройки `channel_pages.steps`, кнопка «Добавить бота
  в группу» — `t.me/<бот>?startgroup=&admin=manage_chat`), в админке — карточки `_channel_cards.html`.
- Дизайн панели — тёмная тема в стиле iOS, единственная. Все цвета — переменные из `base.html` (`--accent`,
  `--green-soft`…), не hex на страницах; переключатель вкл/выкл — `<input type="checkbox" class="switch">`,
  кнопки `secondary` / `danger` (`danger solid` — подтверждение необратимого), сообщения `.notice ok|bad`, подсказки
  `.hint`. В интерфейсе панели без косметических эмодзи (в боте они остаются).
- Время: в базе — UTC (naive, `utcnow()`). Панель показывает его в поясе браузера (`app/web/localtime.py`: cookie
  `tz` из base.html → contextvar; фильтр `|msk` и `tz_label()` в заголовках, «сегодня»/«по дням» — тоже по нему).
  Бот пользователям пишет время в МСК.
- Картинки в панели (сообщения каналов, картинки меню в «Настройках», рассылки) — компонент `_pic.html`: файл уходит на
  сервер сразу при выборе (прогресс поверх картинки), сервер сохраняет исходник и превью WEBP (`app/thumbs.py`,
  колонка `thumb`), страница показывает превью без перезагрузки; нажатие — исходник на весь экран.
- `app/payments.py` — пополнение баланса через Platega (бот: «Баланс» → способ → сумма → счёт), панель «Платежи».
- `app/stars.py` — пополнение звёздами Telegram (XTR, `Payment.provider="stars"`, `method=payments.STARS`). Курс:
  stars_usd ($0,013 — вывод на Fragment) × usd_rate (ЦБ, БЕЗ usd_rate_extra) × (1 − stars_margin %) — тот же курс,
  которым «Сверка» переводит балансы пользователей в $, поэтому запас остаётся у нас. Рубли фиксируются в счёте,
  счёт живёт час (pre_checkout), зачисление — по successful_payment ровно один раз (charge_id в external_id).
  «Сверка»: звёзды бота (getMyStarBalance) × stars_usd. /paysupport обязателен для звёзд.
- Деньги владельцев и кошелёк системы USDT TRC20:
  - `app/owners.py` — владельцы `naomifontaine` и `kindergarten` (вместо общего admin): вход паролем + кодом
    аутентификатора, доля прибыли `share` (50/50). `on_sms` (из `orders.apply_status`) — доля реферала, остаток
    владельцам: (цена − закупка × курс покупки) / курс ЦБ − доля реферала. Только с `profit_since` (день релиза,
    кнопка на «Сверке»). Ручной бонус пользователю — расход владельцев (`bonus_expense`).
  - `app/accounts.py` — счёт владельца или реферала: баланс = сумма движений (`OwnerTransaction`/`RefTransaction`),
    аутентификатор (`app/totp.py`, RFC 6238, резервные коды, 5 неверных — пауза 10 мин), сохранённые адреса, автовывод.
  - `app/tron.py` — сеть TRON: перевод собирается и подписывается локально (txid считаем сами), узел только принимает.
    Комиссия = энергия (не меньше 65 тыс. / 131 тыс. новому адресу) × цена × курс TRX + 10%.
  - `app/payouts.py` — очередь исходящих переводов (`Payout`): выводы, пополнение площадок, оплата счёта
    обменника за TRX («Пополнить TRX» на «Сверке»). Холодного кошелька нет — убран по решению владельцев.
    Подписанный перевод сохраняется ДО отправки; новый — только когда старый истёк и сети неизвестен. Автовывод,
    системные уведомления в Telegram — тем, кто указан в «Настройках» (`notify_users`, @username через запятую;
    `app/bot/notify.py::make_owner_notifier`). Площадки пополняются только кнопкой «Пополнить» по счёту площадки:
    постоянных адресов у них нет, автопополнение убрано.
  - `app/reconcile.py` — «Сверка»: деньги (кошелёк — USDT и TRX по курсу, Platega, площадки) против долгов (балансы пользователей,
    рефералов, владельцев, выводы, оборотные средства). Недостача > $1 — выводы владельцев на паузе.
  - «Сводка» считает только заказы с `profit_since` (до начала учёта — тесты), остальные разделы — все.
  - Панель: «Сверка» (`/reconcile`), «Баланс» владельца (`/balance`, сумма в шапке), «Вывести» (`/withdraw`, общая
    с кабинетом реферала — `app/web/money_pages.py`), «Владельцы» (`/owners`). Служебные команды — `app/cli.py`.
- `app/broadcasts.py` — рассылки: группы получателей `SEGMENTS`, отправка в фоне ≤25/с с продолжением после
  перезапуска (`resume`), отмена = удаление отправленного (Telegram даёт 48 ч). `User.bot_blocked` — заблокировал бота.
- Нижнее меню бота (`ui.MAIN_KB`): «📱 Получить СМС» «🌐 Веб-версия» / «ℹ️ Информация» «👤 Профиль»; в профиле — кнопками
  «💰 Баланс», «📋 Мои заказы», «👥 Пригласить друга» (у каждого «⬅️ Профиль»); их старые кнопки меню тоже работают.
  Картинки разделов (`menu_images.ITEMS`, загрузка в «Настройках», исходники и генератор — `docs/menu-images/gen.py`):
  переход внутри сообщения в раздел с другой картинкой меняет и фото (`handlers.swap_photo`, по `file_unique_id`).
- Бот: сервис → карточка «Авто» (бюджет, страну выбирает бот) или «🌍 Выбрать страну» — страны только по популярности
  (`catalog.country_popularity`: активации сервиса в стране за 30 дней; без данных — дороже выше), кнопок сортировки нет.
  У сервиса в панели «Прим. 1» (`Service.note`: карточка сервиса, экран цены, карточка активации) и «Прим. 2»
  (`Service.note_sms`: в карточке активации под пришедшим кодом). В закрытой активации примечаний нет.
  «Выделить синим» у сервиса в панели (`Service.highlight`) — синяя кнопка в списке сервисов бота (стиль Telegram `primary`).
- Убраны по решению владельца (не возвращать без запроса): анти-фантом, блок-лист «занятых» номеров,
  защита от спама, вопрос о причине отмены, ⭐ на ценах страны, сортировка стран по надёжности.
- `app/providers/` — адаптеры площадок; `app/settings_store.py` — настройки панели (группы `GROUPS`).
- `app/db.py::_add_missing_columns` сам добавляет новые nullable-колонки — миграций нет, новые колонки делать nullable.

## Правила
- Секреты только в `.env` (локально и на сервере), никогда в коде, коммитах и ответах. `.env` не коммитить.
  Ключ кошелька `WALLET_PRIVATE_KEY` не выводить на экран никогда: создаётся сразу в .env
  (`docker compose exec -T app python -m app.cli new-wallet >> .env`).
- Деньги владельцев и рефералов: каждый вывод, сохранение адреса, автовывод, пополнение площадки, настройки денег
  (`SettingDef(secure=True)`), ручное изменение баланса пользователя и проценты реферала — только с кодом аутентификатора
  и только во входе владельца. «Выйти» в панели и в кабинете партнёра закрывает вход на всех устройствах
  (`session_ver` у владельца и реферала), смена/сброс пароля — тоже (кроме текущего входа при смене своего пароля). Реальные переводы
  в сети (тест вывода) — только с разрешения пользователя.
- Тексты для пользователя: «активация SMS», не «купить номер / аренда / аккаунт». Номера стран РФ/УА не продаются
  (`blocked_countries`); сервисы РФ/УА продаются, но не в популярных.
- Реальные покупки номеров (тесты на живых площадках) — только с явного разрешения пользователя.
- Пополнение — Platega (`app/payments.py`): СБП и криптовалюта, ключи `PLATEGA_*` только в `.env`. Зачисление —
  атомарной сменой статуса платежа (не дважды); callback `/webhooks/platega` проверяется по заголовкам и

## Деплой (только с машины пользователя — нужен SSH-ключ `~/.ssh/shifr_new_vps`, пароль root не использовать)
```
tar --exclude='__pycache__' --exclude='*.db' -czf - app requirements.txt | ssh -i ~/.ssh/shifr_new_vps root@SERVER_IP \
  'cd /opt/shifr && tar -xzf - && chown -R root:root app requirements.txt && docker compose up -d --build app && docker builder prune -af >/dev/null'
```
Диск сервера маленький (10 ГБ) — `docker builder prune` после сборки обязателен, иначе кэш сборок за месяцы заполнит диск.

Сервер (с 20.10.2026): Гонконг, 1 ядро, 2 ГБ памяти + 1 ГБ подкачки, Ubuntu 24.04, время UTC. Старый сервер
(SERVER_IP, ключ `~/.ssh/shifr_vps`) остановлен (`docker compose stop`, данные на месте) — запасной, потом удалить.
Логи: `docker compose logs app` в `/opt/shifr` (сбрасываются при пересоздании контейнера).

Домен сайта — только переменная `DOMAIN` в `/opt/shifr/.env` (сейчас shifrsms.shop): из неё Caddy (`Caddyfile`,
через docker-compose) и бот (`config.public_url`). Домен нигде не писать в код и тексты. `Caddyfile` и
`docker-compose.yml` деплоем выше не копируются — после их правки скопировать на сервер отдельно и
`docker compose up -d`.

Защита сервера (18.10.2026, перенесена на новый сервер 20.10.2026): SSH — только по ключу (`/etc/ssh/sshd_config.d/00-shifr-hardening.conf`, пароль выключен),
fail2ban (`/etc/fail2ban/jail.d/shifr-sshd.local`: 3 ошибки за 10 мин — бан на сутки), ufw — открыты только 22, 80, 443,
причём 80 и 443 — только с адресов Cloudflare: блок «SHIFR CLOUDFLARE» в `/etc/ufw/after.rules` (цепочка Docker
`DOCKER-USER` → `shifr-web`; обычные правила ufw трафик к контейнерам не видят). Cloudflare сменил адреса — обновить
список там же (и `trusted_proxies` в Caddyfile) и `ufw reload`. Напрямую по IP сайт не открывается — проверять через домен. У сервера есть публичный IPv6: 80 и 443 в ufw открыты
только для IPv4 (`from 0.0.0.0/0`), иначе через IPv6 docker-proxy пускал бы мимо Cloudflare. `ufw reset` стирает блок
в after.rules — после него вернуть.
Caddy: заголовки безопасности (HSTS, запрет встраивания в чужие страницы), без `Server`/`Via`; сайт за Cloudflare —
адрес посетителя Caddy берёт из `CF-Connecting-IP` только от адресов Cloudflare (`trusted_proxies`) и передаёт приложению
одним `X-Forwarded-For` (лимиты попыток — по нему, `app/web/ratelimit.py`: 10 неудачных входов за 15 мин по адресу и
по логину — в панель и в кабинет партнёра). Резервных копий хостер не делает — свои: `docs/backup.md` (Google Drive
через своё приложение владельца MyBackupProject в Google Cloud, 2 раза в сутки, 14 копий, база + .env, шифрование age — закрытый ключ только у владельца; скрипты — `deploy/backup/`).
